## 1. 整体架构

AI Native 业财经营系统由前端交互、AI Agent、后台应用服务、数据存储、外部系统集成及后台基础设施共同组成。

系统从企业日常业务中持续获取信息，通过 AI 完成非结构化信息的理解和整理，通过后台应用服务执行确定的业务规则，并将经过确认的业务事实形成正式业务数据。

正式业务数据按照项目及相关业务关系持续关联，并进一步形成财务数据和经营数据，最终支持项目管理和经营分析。

整体形成：

业务发生 → 信息进入系统 → AI 理解与整理 → 业务规则处理 → 正式业务数据 → 财务与经营计算 → 经营数据 → 前端展示与业务操作

## 2. 前端与交互层

前端是用户与系统发生交互的入口，同时负责展示系统已经形成的业务状态和经营结果。

业务操作入口

系统提供工作台、项目管理、沟通中心、合作管理、财务运营和经营分析等结构化工作区域。

用户可以直接查看和处理项目、合作、合同、结算、财务及经营事项。

AI Native 交互入口

用户也可以通过自然语言、长语音、沟通记录、合同、发票、Excel、图片等方式直接提交业务信息。

AI 根据当前用户、项目、合作对象及系统已有数据理解输入内容，识别其中的业务事实，并形成待确认的信息。

系统因此支持两类业务入口：

结构化页面操作 → 直接形成结构化请求

自然语言 / 语音 / 文件 → AI 理解 → 形成结构化请求

两种方式最终进入同一套业务处理流程。

## 3. 核心业务数据处理

系统将日常业务中零碎、杂乱的信息逐步整理为正式业务数据，并通过数据关联、财务规则和经营计算，最终形成可用于经营管理的数据。

完整处理链路为：

零碎、杂乱的业务信息 → 结构化信息 → 正式业务数据 → 项目归集与财务数据 → 费用分摊与经营计算 → 经营数据

第一步：零碎业务信息 → 结构化信息

自然语言、语音、沟通记录、合同、发票、Excel 等零碎、杂乱的信息进入系统后，由 AI Agent 结合当前用户、项目、合作对象和已有业务记录理解业务上下文。

AI Agent 从中识别业务对象、金额、日期、合作条件、合同条件和状态变化等关键事实，将原本分散、表达方式不统一的信息整理成系统能够继续处理的结构化信息。

零碎、杂乱的业务信息 → AI Agent 理解与整理 → 结构化信息

第二步：结构化信息 → 正式业务数据

AI Agent 根据业务事项调用对应技能。技能定义该类业务事项的处理程序，并通过工具读取已有数据、检查业务状态和调用后台能力。

涉及正式业务事实的信息由用户检查、修改并确认。人工确认后，后台应用服务按照 [BUSINESS_LOGIC.md](BUSINESS_LOGIC.md) 中确定的业务规则完成校验、业务条件判断、数据关联和状态更新，生成或更新对应的正式业务记录。

结构化信息 → 技能与工具处理 → 人工确认 → 后台执行业务规则 → 正式业务数据

第三步：正式业务数据 → 项目归集

正式业务数据写入系统时，同时建立与项目及相关业务记录之间的关系。

项目创建时形成唯一项目编号。后续合作、合同、结算、收入、成本、发票、应收应付和收付款等数据持续关联到对应项目，更具体的业务关系通过合作、合同、结算等记录继续连接。

由此，不同业务环节产生的数据能够持续归集到同一个项目。

正式业务数据 → 建立业务关系 → 按项目归集

第四步：业务数据 → 财务数据

后台根据已经确认的业务数据和确定的业务规则，判断业务事项产生的财务影响，并生成或更新相应的收入、成本、应收、应付、发票和收付款记录。

这些财务记录继续保留项目及业务来源关系，使业务执行与财务结果保持连接。

项目业务数据 + 业务规则 → 收入 / 成本 / 应收 / 应付 / 发票 / 收付款

第五步：财务数据 → 经营数据

能够直接归属于项目的收入和成本直接进入对应项目；公司公共费用按照既定分摊规则分配至各项目。

完成归集和分摊后，系统按照统一经营口径计算项目预算、收入、成本、利润、应收应付和资金数据，并进一步按照客户、时间等维度汇总形成公司经营数据。

示例

业务员语音：“Mia 这边已经确认了，小红书一篇 8,000 元，平台服务费 5%，用她的小红书账号发布，客户也确认可以合作。”

↓  
结构化信息

项目：十月新品内容推广｜达人：Mia｜平台：小红书｜合作金额：¥8,000｜平台服务费率：5%｜合作状态：已确认｜客户确认：是

↓  
正式业务数据

达人合作：Mia / ¥8,000 / 已确认｜达人结算：¥8,000｜平台服务费：¥400｜项目归属：十月新品内容推广

↓  
项目归集

达人执行成本：¥8,000｜平台服务费：¥400｜本次新增项目成本：¥8,400

↓  
财务数据

项目成本：¥8,400｜应付达人：¥8,000｜应付平台：¥400｜进项发票：待收到｜付款状态：待付款

↓  
经营数据

项目预算：¥145,000｜更新后已用预算：¥139,700｜剩余预算：¥5,300｜预算使用率：96.3%｜项目利润及现金流数据同步更新

## 4. 数据库与文件存储

数据层负责保存系统已经形成的正式业务数据、数据关系及原始业务资料，为业务处理和经营计算提供统一数据基础。

数据库

数据库保存项目、合作、合同、结算、收入、成本、发票、应收应付、收付款等结构化数据。

项目创建时形成唯一项目编号。后续与该项目有关的业务和财务记录持续记录自己的项目归属，更具体的业务关系再通过合作、合同、结算等记录继续连接。

因此，数据库承担三个主要作用：

保存正式数据 + 保留数据关系 + 为业务处理和经营计算提供统一数据源

文件存储

文件存储保存合同原件、发票图片、Excel、沟通记录及其他原始业务资料。

文件与数据库中的项目、合同、结算、发票等对应记录关联，使结构化数据能够追溯到原始业务依据。

## 5. 外部系统集成

外部系统集成负责将企业微信、邮件、银行、内容平台等外部信息接入系统的数据处理流程。

接入方式

根据不同系统开放的能力，可以采用 API、Webhook、定时同步或文件导入等方式获取数据。

沟通渠道可以通过接口或消息推送获取沟通内容；银行和内容平台可以通过接口或定时同步获取交易及业务数据；Excel、银行流水等也可以通过文件导入进入系统。

进入系统后的处理

沟通、合同等非结构化信息进入 AI Agent，由 AI Agent 完成理解和业务对象匹配，再进入人工确认和后台处理流程。

银行流水、平台数据等已经结构化的信息直接进入匹配和校验流程。

确认后的数据写入对应业务记录，并关联到相关项目，继续参与后续财务和经营计算。

## 6. 后台基础能力

生产系统需要一组贯穿业务处理、数据存储和外部集成的后台基础能力，以保证系统能够稳定、安全地处理真实企业数据。

API 服务

前端、AI Agent 和外部系统通过后台 API 读取和更新系统数据。

API 将前端操作与数据库隔离，使所有正式数据操作统一经过后台业务规则、权限和数据校验。

身份认证与权限

后台识别当前用户及其角色，并根据权限控制用户可以查看和操作的项目、财务数据及管理信息。

同一套业务数据可以根据管理者、项目团队等不同职责形成相应的信息范围和操作权限。

后台任务

合同解析、批量文件处理、AI 调用、银行流水匹配、外部平台同步等耗时任务可以通过后台任务异步执行。

系统负责记录任务状态，并对失败任务进行重试或异常处理。

日志与审计

系统记录关键数据的创建、修改和确认过程，包括操作人员、时间、修改内容以及 AI 参与和人工确认情况。

业务状态和经营数据能够追溯到具体的数据变化和业务操作。

异常与安全控制

后台统一处理接口失败、数据重复、同步异常、AI 调用失败等运行异常，并通过访问控制、敏感数据保护、密钥管理和数据加密等机制保护企业数据。

## 7. 部署与运行架构

生产环境需要将前端、后台服务、数据库、文件存储、LLM 和外部系统接口部署为可以持续运行的完整系统。

整体运行关系可以概括为：

用户 → 前端应用 → 后台 API / AI Agent → 后台应用服务 → 数据库与文件存储

同时：

后台服务 ↔ LLM

后台服务 ↔ 企业微信 / 银行 / 内容平台等外部系统

生产环境还需要配置开发、测试和生产环境，以及自动部署、系统监控、错误告警、数据备份和恢复等运行机制，保证系统能够持续稳定运行。

## 8. Concept Demo 与生产级边界

当前版本完成到 Concept Demo 阶段，重点验证系统的业务流程、数据关系、经营规则、AI Native 工作方式及整体产品交互。

生产级落地

进入生产开发后，需要由工程团队将已经验证的业务流程、数据关系和经营规则实现为真实后台服务和数据库，并完成 AI Agent、LLM、外部系统 API 及文件存储等实际集成。

同时需要建设身份与权限、后台任务、日志审计、异常处理、安全控制、测试、监控、备份和部署运维等生产环境能力。

当前已经完成

当前 Demo 已经实现主要产品界面和可交互业务流程，并建立项目、合作、合同、结算、发票、应收应付、资金和经营分析之间的数据关系。

项目状态、预算、收入、成本、利润及相关经营数据已经按照统一业务逻辑进行关联和计算。

小A模拟 AI Agent 从业务信息理解、整理、人工确认到数据更新的完整过程，用于验证 AI 在业务流程中的参与方式。

当前版本已经能够验证：

业务流程 + 数据关系 + 经营规则 + AI 参与机制 + 产品交互 + 经营结果

当前实现边界

当前 Demo 主要运行在浏览器端。

正式后台服务和数据库尚未搭建，当前由前端代码、演示数据和浏览器本地存储模拟业务处理、数据状态及部分经营计算。

小A模拟 AI Agent 的处理结果，尚未接入真实 LLM；企业微信、银行和内容平台等外部系统也尚未连接真实接口。

因此，当前交付成果属于对产品方案和系统逻辑的可交互验证。
