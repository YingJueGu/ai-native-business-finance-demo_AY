## 1. 产品概述

AI Native 业财经营系统面向项目制营销服务企业，将项目执行、业务协作、合同结算、经营财务和经营分析纳入统一管理体系。

系统通过 AI 获取和整理日常业务信息，并将其持续转化为结构化业务数据和经营数据，形成从业务执行到经营管理的完整闭环。

## 2. 产品架构

系统围绕项目经营构建，由六个主要工作区域组成：

工作台 / 项目管理 / 沟通中心 / 合作管理 / 财务运营 / 经营分析

其中，工作台是用户日常工作的主要入口；项目管理承载项目全过程；沟通中心连接日常沟通与业务状态；合作管理维护长期业务对象；财务运营承接项目产生的结算和资金事项；经营分析将业务数据进一步转化为管理信息。

小A作为全局 AI 业务助手贯穿各工作区域，协助完成业务信息获取、整理、关联、查询和处理。

工作台

工作台是系统的主要工作区域，也是业务信息进入系统的核心入口。

用户可以通过自然语言、长语音、图片、Excel、PDF、合同、发票、截图及多文件等方式直接提交业务信息或发起业务操作。

小A结合当前用户、项目、合作对象及系统已有数据理解业务内容，识别关键事实及其业务关系，形成相应的整理结果或业务操作。业务事实由用户检查、修改并人工确认后写入正式业务数据。

核心交互机制：

业务输入 → AI 理解与整理 → 业务对象匹配 → 人工确认 → 数据更新

工作台同时聚合当前用户最相关的任务、项目和经营信息。管理者侧重公司项目状态、经营和资金事项；项目团队侧重本人任务、参与项目及日常业务处理。

项目管理

项目管理承载项目从方案、执行、内容交付到合同结算的全过程。

每个项目形成统一的项目工作空间：

概览 / 方案 / 达人 / 内容与数据 / 合同与结算 / 项目记录

项目状态、方案版本、合作执行、内容交付、预算、合同、结算及相关业务记录在同一项目下持续关联，使项目执行过程与经营结果保持连接。

沟通中心

沟通中心负责管理项目相关业务沟通，并通过 AI 将非结构化沟通内容转化为可处理的业务信息。

小A结合沟通上下文、合作对象和关联项目，识别报价、合作条件、关键时间节点、客户反馈、执行状态及潜在风险，形成结构化整理结果、业务更新或后续任务。

经过人工确认的信息进入对应项目及业务记录，使沟通成为业务数据持续形成的重要来源。

合作管理

统一管理客户、达人、平台和供应商等合作对象，以及相关账户、历史合作记录和业务关系，为项目执行、结算及经营分析提供基础数据。

财务运营

集中管理项目经营过程中形成的应收、应付、销售及进项发票、收付款和相关异常事项。

财务数据与项目、合同及结算来源保持关联，使资金结果能够持续追溯至具体业务。

经营分析

将项目执行和财务运营过程中形成的数据汇总为管理层使用的经营信息。

当前版本优先覆盖项目经营、客户经营、应收与回款、现金流预测和项目经营状态等基础且高频的管理需求，帮助管理层掌握项目经营结果、客户贡献、回款进度、未来资金情况及重点项目状态。

经营分析体系可根据企业规模、业务模式和管理需求进一步扩展指标、分析维度和管理视图。

## 3. 业务闭环与 Workflow

系统以项目为主线，将业务执行与经营结果持续连接。

项目创建 → 方案制作 → 客户确认 → 合同签署 → 达人执行 → 内容审核 → 发布 → 客户验收 → 结算 → 完成

项目推进过程中，合作、内容、合同、费用、发票和收付款等业务事项持续与项目关联。

项目执行完成后，系统分别跟踪业务履约和财务结算状态，使项目从业务启动持续管理至最终经营闭环。

业务过程最终形成：

项目执行 → 业务履约 → 合同结算 → 收入与成本 → 应收应付 → 收付款 → 项目经营结果

## 4. 业务数据形成机制

系统中的经营数据由业务过程中持续产生的信息逐步形成。AI 负责识别和整理信息，业务人员确认业务事实，系统再依据既定的业务关系、经营规则和计算口径完成数据归集、计算和汇总。

业务信息 → AI 识别与整理 → 人工确认 → 业务数据形成 → 规则归集与计算 → 经营数据 → 管理视图

信息识别与整理

系统从自然语言、语音、沟通记录、合同、方案、报价、发票、Excel 及其他业务资料中识别项目、客户、合作对象、金额、日期、合同条件、业务状态等信息，并匹配已有业务对象。

人工确认与数据形成

AI 将识别结果整理为待确认的业务信息，由业务人员检查、修改并确认。确认后的业务事实写入对应的项目、合作、合同、结算及财务记录，成为正式业务数据。

业务归集与经营计算

系统按照既定的业务关系和经营规则处理正式业务数据。例如，将不同合作方产生的成本归集至对应项目和结算事项，根据合同和结算安排形成应收应付，根据预算及费用规则归集项目成本，并按照统一经营口径计算项目收入、成本、利润和资金情况。

经营数据汇总

项目层面的经营数据进一步按照项目、客户、时间和资金等管理维度汇总，形成项目经营、客户经营、应收回款、现金流等管理视图，并保留从经营结果向具体业务记录的追溯关系。

## 5. 核心设计思路

低负担信息归集

将信息获取融入实际业务过程，通过自然语言、语音、沟通和文件持续获取业务信息，减少额外记录和重复整理。

业务与经营一体化

以项目为主线连接业务执行、合同、结算、发票和资金，使经营数据伴随业务推进持续形成。

AI Native 交互

AI 参与业务信息的理解、整理、关联和处理，使用户能够以更接近日常工作方式的交互完成业务操作。

关键事项确认

业务事实由人工确认后进入正式系统，在提升信息处理效率的同时保持业务数据可靠。

统一数据基础

项目、合作对象、合同、结算、发票和资金建立持续的数据关联，为跨业务环节追溯和经营分析提供基础。

角色化工作视图

管理者和项目团队基于同一套业务数据，根据各自职责获得相应的任务、项目和经营信息。
