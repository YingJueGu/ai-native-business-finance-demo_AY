# AI Native 业财经营系统

中文 | [English](README_EN.md)

面向项目制营销服务企业设计的 AI Native 业财经营系统。

本项目基于真实企业经营场景展开。项目从业务调研和经营问题诊断开始，对企业现有项目运作方式、人员协作、业务信息流转以及经营管理需求进行梳理，并在此基础上重新设计项目经营流程、业务规则、数据关系和管理视图，进一步探索 AI Native 环境下更低操作负担的业务系统交互方式。

当前版本为可交互 Concept Demo，用于验证整体经营管理框架、核心业务逻辑及 AI Native 工作方式。

## 项目背景

企业是一家小型营销服务公司，主要为品牌客户提供项目制营销服务。团队规模精简，业务人员同时承担客户沟通、方案推进、达人合作、内容执行及项目跟进等工作，缺少独立的大型运营或财务后台团队。

一个项目通常会经历客户需求、方案制定、达人筛选与询价、合作确认、合同及下单、内容制作与审核、发布、数据跟踪、结算、开票和回款等多个环节。项目推进过程中持续产生大量业务信息，包括客户要求、达人报价、合作条件、交付节点、合同约定、费用、发票及收付款安排。

现有工作方式能够支撑项目交付，但经营信息长期分散在聊天记录、Excel、合同与发票文件、平台后台、邮件及个人记录中。不同人员分别掌握部分信息，同一业务事实经常需要重复记录、手工核对和再次整理。

核心痛点：

- 人工记录负担重 — 项目推进高度依赖人工记录和跟进。业务人员需要不断在聊天、表格、文件和平台之间切换，重复查找、核对和更新信息，项目增加后容易出现遗漏。
- 业务数据分散凌乱 — 项目、客户、达人、合同、费用、发票和资金信息分散在不同工具和人员手中，记录方式和数据格式不统一，信息之间缺少稳定关联，难以形成完整、持续的数据基础。
- 经营管理能力不足 — 企业能够持续推进业务，但项目执行与经营结果之间缺少系统化连接。项目利润、预算使用、应收回款和未来现金流依赖事后人工整理，管理层难以及时掌握经营情况并提前干预。

因此，本项目从项目实际运作方式出发，重新设计业务执行、经营数据和管理信息之间的关系，使关键经营事实在业务发生过程中持续沉淀，并最终形成可用于项目管理、资金安排和经营决策的数据基础。

## 解决方案

系统以项目经营为主线，将项目执行、合作方、合同、结算、发票、应收应付和资金信息纳入统一管理框架。

业务人员通过工作台、日常沟通、语音和文件推进工作。AI 从这些业务信息中识别项目、合作对象、金额、日期、合同条件和状态变化，整理为结构化信息；业务事实由人工确认后进入正式系统，并通过统一的数据关系串联项目、合同、结算、发票和收付款。

随着项目推进，系统持续形成项目状态、预算、收入、成本、应收应付和现金流数据，并进一步汇总为管理层需要的经营信息。

方案亮点：

- 低负担信息归集 — 让业务信息尽可能在日常工作过程中自然沉淀。AI 从语音、沟通和文件中识别、整理并关联业务信息，减少额外记录、重复录入和系统维护的工作量。
- 经营管理体系落地 — 将项目执行、合同、结算、发票和资金连接起来，使业务过程持续形成收入、成本、利润、应收应付和现金流数据，并进一步形成项目经营、客户经营、回款和现金流等管理视图。
- AI Native 工作方式 — 用户可以直接通过自然语言、语音、沟通和文件与系统协作。AI 负责理解和整理业务信息，规则系统负责关键计算与状态控制，业务事实由人工确认后进入正式系统，使 AI 真正进入业务流程。

整体形成：

业务发生 → 信息获取 → 数据形成 → 经营分析 → 管理决策

AI 负责非结构化信息的理解和整理，业务规则负责金额、状态、权限和计算，业务事实由人工确认后进入正式系统，数据库保存经过确认的正式业务事实。

## 系统结构

系统从企业日常业务中获取信息，并将这些信息逐步转化为可用于经营管理的数据。

1. 业务信息进入系统

   业务人员通过文字、语音、沟通记录和文件处理日常工作，业务信息由此进入系统。

2. 形成结构化业务数据

   AI 理解和整理输入内容，识别其中的关键业务信息，并结合业务规则和人工确认，将其转化为正式、可关联的业务数据。

3. 形成经营数据

   随着项目持续推进，系统按照既定的业务关系、经营规则和管理口径，对业务数据进行关联、计算和汇总，逐步形成项目及公司层面的经营数据。

4. 支持经营管理

   管理层通过经营视图掌握项目经营、客户经营、回款和现金流等情况，并可进一步追溯至具体业务记录。

## 我的角色

项目负责人 / 经营管理与产品方案设计

负责项目从业务调研、需求识别与问题诊断，到经营管理方案、业务流程与规则、数据关系、AI Native 工作方式及产品方案设计的整体推进，并通过 AI-assisted / Vibe Coding 完成可交互 Concept Demo 的搭建与迭代验证。

当前项目交付至 Concept Demo 阶段，用于验证业务方案、经营逻辑、系统设计和产品交互。

生产级部署不在本项目当前工作范围内。正式部署需要专业工程团队进一步完成后端服务、数据库、身份与权限、安全控制、真实 LLM 与第三方 API 集成、测试、部署及运维等工程工作。

## Data & Privacy

公开版本仅用于方案展示。

企业、客户、员工、达人、供应商、合同、发票、金额、日期、沟通内容及其他业务记录均经过匿名化、调整或重新构造，不代表真实企业经营记录。

公开仓库不包含真实合同、发票、银行信息、聊天记录、客户资料、商业机密、API Key 或其他敏感信息。
